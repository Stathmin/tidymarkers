## 0. Что уже есть и что не входит

Опора программы — не новая архитектура, а уже принятые решения и замеры:

- ADR 0005 (индексная стратегия), 0006 (швы панели), 0007 (швы модулей и
  MCP-контракт); `ZT T1`–`T13` закрыли индекс, шарды, BiocParallel, фикстуру
  фазовых гаплотипов, оркестратор панели, реестры `plot`/`print`, разрезание
  god-файлов, валидацию `tools/call`, `digest`/`processx` и vctrs-класс.
- Замеры: TAIR10 memory vs per-chromosome bowtie — медиана 18.64 с vs 18.32 с,
  индекс/память 0.98×, максимум 1.18×; `VmHWM` — 1.7 Б/п.н. над baseline,
  консервативный бюджет 5 Б/п.н.; монолит 16 Гб = 21.5 ГБ индекса не влезает
  в 16 ГБ RAM (`docs/decisions/0001-16gb-fixpur.md`).
- Дефекты, которые программа закрывает: ZU1 (`panel` — тупик), ZU2 (`outcomes`
  — тупик), ZU3 (`report` — тупик), ZU4 (`primers` — два контракта), ZU5
  (справочники без моста), ZU6 (нет генотипов и строки `variant`), ZU7
  (дубликаты/дрейф описания), ZU8 (граф и CSV гниют).

**Не входит:** новая наука `Z7`/`Z8`, Rust-адаптер, DuckDB, новые химии,
GUI, CRAN-сабмит, Python-клиент MCP, второй диалект схемы. Всё это — отдельные
решения, а не трёхдневный объём.

### Правила программы

1. Этот коммит — только документы: ADR 0008–0011, §ZV, этот план, ссылки в
   `docs/INDEX.md` и `docs/adr/README.md`.
2. Блокер не останавливает программу: классификация → repair-задача →
   починка/обход → quarantine, если не вышло, и сразу следующая задача.
   Красный гейт — это блокер, а не остановка дня; объём срезается, но lane
   продолжает работать.
3. Вердикт на золотом наборе не меняется ни одним рефакторингом (`D1`–`D5`).
4. Новый экспорт допустим только вместе со строкой в
   `docs/user-api-surface.csv`, обновлённым DOT и названным владельцем (ADR или
   ZV). Иначе — не экспорт.
5. Пользовательский шаг не требует `$`, `[[` или ручного вытаскивания колонки.
   Мост — экспортированный аксессор (`as_marker_solved()`,
   `as_primer_set()`), а не знание внутренней формы.
6. Срез при отставании: сначала `ZV3`/`ZV4`, затем `ZV5`; `ZV1`, `ZV2`,
   `ZV6`, `ZV9`, `ZV10` не срезаются.

## 0.1 Контракт метрик — с первого дня, не в конце

Метрики — такой же контракт, как сценарии и артефакт. Базовый прогон
снимается на `main` **до** первой правки кода; каждый следующий прогон пишет
тот же формат. Прогон без строки метрик не считается прогоном.

**Файл:** `data/metrics/<date>-<run>.jsonl` — один JSON-объект на строку, одна
строка на стадию. Поля фиксированы:

| Поле | Тип | Смысл |
| ---- | --- | ----- |
| `run_id` | string | стабильный id прогона; для reproducibility-прогона детерминирован |
| `stage` | enum | `scenario`, `ingest`, `design`, `specificity`, `thermo`, `checks`, `artefact`, `mcp`, `gate`, `repair` |
| `object_id` | string | id, `artefact_id` или `scenario:JN`; не свободный текст |
| `duration_ms` | integer | длительность стадии |
| `status` | enum | `ok`, `warn`, `fail`, `skip`, `error` |
| `retries` | integer | повторы после первой попытки |
| `tokens_in` | integer/null | входные токены LLM; null, если модель не вызывалась |
| `tokens_out` | integer/null | выходные токены LLM; null, если модель не вызывалась |
| `cost_usd` | number/null | оплаченная стоимость; `0` для локального счёта, null если неизвестна |
| `cache_hit` | boolean | стадия переиспользовала шард, артефакт или кэш |
| `queue_depth` | integer | задач в очереди на старте стадии |
| `gpu_util` | number/null | загрузка GPU в долях 0–1; null для не-GPU стадии |
| `language` | string | `en`, `ru` или `und`; язык прогона, не текст |

**Содержимого нет.** Промпты, последовательности, метки целей, пути и тексты
ошибок в метрики не пишутся. `object_id` — id или хеш, не метка. Валидатор
`dev/metrics.R --check` отвергает неизвестные ключи, поэтому `prompt`,
`content` или `sequence` — красный гейт, а не «строчка для отладки».

**Кто пишет.** Стадии пакета пишут `tokens_in = null`, `tokens_out = null`,
`cost_usd = 0`; это локальный R. Обёртка агента/LLM, которая ведёт программу,
пишет те же поля с реальными числами. Смешанный маршрут — один файл и одна
схема.

**Дневной срез.** `Rscript dev/metrics.R --report <date>` пишет
`data/metrics/metrics-<date>.md`:

- p50/p95 `duration_ms` по стадиям (nearest-rank); стадия с `n < 20` —
  `insufficient_n`, не процентиль;
- пропускная способность: завершённых прогонов в час и в день;
- стоимость на маршрут J1–J7: `sum(cost_usd) / число прогонов маршрута`;
- доля провалов `(fail + error) / total` по стадии и маршруту;
- cache-hit rate и p95 `queue_depth`;
- самопочинка: блокеров/час, MTTR, доля авто-решённых, задач на блокер.

Итоговый отчёт программы — `data/metrics/metrics-<date>.md` с дельтой к
baseline по каждой стадии и маршруту.

**Гейты метрик:**

1. `p95(stage, route) <= p95_baseline(stage, route)` для каждой пары с
   baseline, одинаковым набором `run_id` и `n >= 20` с обеих сторон; иначе
   `not_run` с числом сэмплов и причиной. Стадийная дельта в отчёте —
   статистика, не вердикт ([ADR 0013](../adr/0013-metrics-gate-is-not-a-green-delta.md)).
2. `cost_per_route(JN) <= cost_per_route_baseline(JN)` для J1–J7; если baseline
   равен нулю, любая billed-стоимость — красный.
3. Повторный прогон байт-идентичен: выход маршрута (`artefact.json`, CSV)
   сравнивается байтами при фиксированном `SOURCE_DATE_EPOCH`; сырой JSONL
   байтами не сравнивается, потому что `duration_ms` и `queue_depth` разные.
   Гейт сравнивает канонический срез без `duration_ms`, `queue_depth` и
   `cache_hit`; тайминги проверяются p50/p95.
4. Доля провалов выше baseline — красный дневной отчёт даже при зелёном p95;
   отчёт называет стадию и маршрут.
5. Блокер без строки в `docs/plans/self-repair-log.md` дольше 10 минут —
   красный; `blockers/hour`, `MTTR`, `auto-resolved share` и `tasks per
   blocker` есть в дневном отчёте.

## 0.2 Autonomy & self-repair — блокер не останавливает программу

Правило: **блокер никогда не останавливает программу.** Заблокированная задача
уходит в repair-lane, основной поток сразу берёт следующую. Гейт не
ослабляется; меняется только то, что происходит, пока он красный. Полный
протокол — [ADR 0012](../adr/0012-autonomy-and-self-repair.md).

**Протокол.**

1. **Детект и классификация.** Класс выбирает маршрут и бюджет:

   | Класс | Сигналы | Действие по умолчанию |
   | ----- | ------- | --------------------- |
   | `transient` | 429, таймаут, rate limit, обрыв соединения, один флейки-процесс | retry с backoff; код не меняется; число повторов в лог |
   | `environment` | нет пакета, бинаря, движка, не тот R-библиотека | установить/указать окружение (`dev/install-deps.R`, `marker_install_tools()`, `R_LIBS_SITE`); не пропускать молча |
   | `data` | нет полного текста, фикстуры, файла, колонки | взять из названного источника; если нельзя — сгенерировать фикстуру из измеренных данных с записанным допущением; не выдумывать значение |
   | `access` | нет ключа, истёк доступ, read-only | read-only обход; вопрос человеку; не угадывать секрет |
   | `logic` | воспроизводимый баг, падающий тест, неверный вердикт | воспроизвести, минимальная правка в общем корне, регрессионный тест |
   | `spec` | неясность, два чтения порога, нет названного источника | консервативный дефолт + revisit-пометка + асинхронный вопрос; политику не выдумывать |
   | `external` | инструмент падает, сервис недоступен, несовместимый релиз, нет XSD | фолбэк или замена, пин версии; если фолбэка нет — quarantine |

2. **Repair-задача в очередь.** `R-<n>` с классом, приоритетом (`P0` — J1/J6/J7
   или релизный гейт, `P1` — пункт дня, `P2` — полировка), бюджетом
   **≤ 30 минут на попытку, ≤ 3 попытки** (90 минут на блокер), владельцем и
   следующей задачей.
3. **Починка или обход.** Сначала root cause + тест; если нельзя — объявленный
   фолбэк (pure-R термодинамика, memory-стратегия, кэш-фикстура, фоновый
   `R CMD check`), с записанным ограничением.
4. **Quarantine, если не вышло.** Записать риск, влияние, консервативный
   дефолт (если есть), вопрос человеку и дату revisit. Пункт остаётся открытым;
   это не закрытие. Сразу взять следующую задачу.
5. **Лог.** Всё писать в
   [`docs/plans/self-repair-log.md`](self-repair-log.md): время, блокер, класс,
   действие, результат, коммит, попытка, статус, следующая задача. Лог
   append-only, без секретов и содержимого данных.

**Анти-простой.**

- В очереди всегда **3 следующие задачи**; если меньше — создать до запуска.
- У каждой задачи time-box; repair-попытка не длиннее 30 минут.
- **Watchdog:** нет коммита и нет прогресса в логе **45 минут** → переключение
  на следующую задачу и строка `watchdog` в логе.
- Repair-lane не блокирует основную: у неё свой бюджет и свой слот; main-lane
  не ждёт её.

**Запреты.** Не выдумывать данные; не ослаблять и не удалять тесты; не пушить
в `main` без гейта; не делать необратимое (удаление данных, перезапись истории,
смена опубликованного контракта, трата денег, ротация ключа) без человека.
Нарушение запрета — не repair, а остановка до человека.

**Метрики самопочинки.** Из лога и `stage = "repair"` JSONL в дневной отчёт:
блокеров/час, MTTR, доля авто-решённых `(fixed + bypassed) / all`, задач на
блокер. Quarantine считается отдельно и в MTTR не складывается. Рост
blockers/hour и доля quarantine > 30% — сигнал процесса, не повод остановиться.

**Известные блокеры и обходы.**

| Блокер | Класс | Обход |
| ------ | ----- | ----- |
| Нет Bioc-пакета (`GenomicRanges`, `Rsamtools`, `DECIPHER`, …) | environment | `Rscript dev/install-deps.R`; `BiocManager::install()` с пином; проверить `requireNamespace()`. Если хост не ставит — quarantine внешнего сьюта, pure-R тесты остаются зелёными. |
| Внешний бинарь падает/отсутствует (OligoArrayAux, BLAST, bowtie, ImageMagick) | environment / external | pure-R фолбэк (`internal_duplex_dg()`, `internal_hairpin_dg()`), memory-стратегия, другой движок через `specificity_of()`; пин версии; если фолбэка нет — quarantine утверждения. |
| Нет фикстуры или полного текста | data | сгенерировать из названного источника, допущение — в `docs/decisions/` или `inst/extdata/`; синтетическая scale-фикстура помечается synthetic; измеренное число не выдумывать. |
| Нужен человек (порог, политика, релиз) | spec / access | консервативный дефолт из реестра (нет LD-дефолта, нет p-value cut, `calibrated = FALSE`), revisit-пометка, асинхронный вопрос, следующая задача. |
| `R CMD check` долгий (~7 мин) | transient / environment | запустить в фоне, продолжить lane, забрать результат; не запускать дважды на одном дереве. |
| Нет 16 ГБ fixpur на хосте | data / environment | три сборки + synthetic 250 Мб; реальный прогон — операторское действие в `docs/decisions/0001-16gb-fixpur.md`; не заявлять измеренный 16 Гб. |
| Сеть/Ensembl Plants недоступны | external | коммиченная FASTA/транскриптная фикстура или кэш; тесты не требуют живой загрузки. |
| Движок нужен сценарию, но отсутствует | environment | контрактный шаг без движка всё равно проверяется; design-шаг — объявленный skip, не pass; сценарий помечается degraded. |
| Рефакторинг меняет вердикт | logic | не мержить пункт, воспроизвести на золотом наборе, починить корень; golden не ослаблять. |
| Нет XSD для ST.26 | data / external | структурная проверка по коммиченной схеме; иначе quarantine валидации с вопросом про XSD, экспорт сохранить. |

## 0.3 Календарь, а не чек-лист

День заканчивается по часам, а не по выполненному списку. Формальная граница —
**00:00**, работа идёт непрерывно до **00:00 понедельника 2026-11-30**: День 1
не «закрывается», он заканчивается по календарю, и сразу начинается День 2.

- Пункты текущего дня кончились — бери следующий открытый пункт `ROADMAP.md`
  (§ZV и далее), не останавливайся.
- Открытых пунктов нет — закалка: полный прогон тестов, регрессии,
  архитектурные проверки, перф, аудит зависимостей, безопасность,
  документация.
- `day-N-gate.md` — отчёт о состоянии на момент времени, не разрешение
  остановиться. Гейт может быть красным, lane продолжается.
- Блокер — это repair-задача (ADR 0012), а не пауза: watchdog, ≤3 попытки по
  30 минут, quarantine с точным вопросом, следующая задача.
- Простой запрещён. «Нечего делать» означает «взять закалку из §8», а не ждать.

## 0.4 Дни — ориентир, не барьер

Разбиение на дни нужно для порядка, а не для блокировки. Пункт Дня 2 или Дня 3,
который не зависит от незакрытого пункта, делается **сразу**, в День 1.
Параллель дороже последовательности.

- Зависимость — это типизированное ребро (`docs/user-api-surface.csv`) или
  явная ссылка «нужен X» в тексте пункта. Всё остальное — не зависимость.
- Независимые пункты можно брать в любом порядке и вести параллельно; блокер
  одного лейна не останавливает другой.
- Когда план исчерпан или всё разблокированное закрыто — мета-работа: новый
  ADR по найденному дефекту, новые пункты `ROADMAP.md`, гигиена кода
  (мёртвый код, дубли, раздутые файлы, доки, линтеры).
- Мета-работа коммитится так же, как обычная задача: отдельный коммит с
  причиной, а не «попутно».

## 0.5 Каденция мержа

`main` двигается только по маркеру, а не по настроению.

- Дневной гейт прошёл → `touch data/metrics/gate-green-$(date +%F)`, коммит и
  пуш `program/3day-20261127`. Маркер — разрешение на мерж, отчёт гейта — его
  объяснение.
- Steward каждые 4 часа: `dev/steward.sh sync` — мержит `origin/main` в
  `program/3day-20261127` и `chore/hygiene-20261127`, пушит.
- Steward в 00:05: `dev/steward.sh merge` — при наличии маркера за прошлый день
  вливает обе рабочие ветки в `main` и пушит; без маркера `main` не двигается.
- Новые ветки не плодятся: работа только в `program/3day-20261127` или
  `chore/hygiene-20261127`. Слитые ветки удаляются локально и на `origin`.
  Две названные lane-ветки остаются: они несут следующий день.

## 0.6 Блокер — это исследовательская задача

Блокер не означает «нужен человек». Первое действие — поиск состояния
искусства на 2026 год: OpenAlex, Crossref, Europe PMC, arXiv, ToolUniverse
(`find_tools`) и веб. Минимум 3–5 источников с DOI/URL и выжимка «что
рекомендуют в 2026», затем выбор решения. Решение оформляется файлом в
`docs/decisions/` (или ADR) с альтернативами, после чего реализуется и
проверяется. Человеку эскалируется только доступ, креды или необратимое
действие. Каждый блокер пишется в `/tmp/opencode/blockers-tidymarkers.md`;
супервизор превращает его в SOTA-задачу.

## 4. Что делается параллельно

| День | Параллельно | Последовательно | Критический путь |
| ---- | ----------- | --------------- | ---------------- |
| 1 | D — первым, затем A (ZV1), B (ZV2/ZV3), C (ZV4/ZV5) | baseline D → мерж A → C → B | ZV1 → ZV2 |
| 2 | A (ZV6), B (ZV7), C (ZV8) | мерж A → B → C | ZV2 → ZV6 |
| 3 | A (ZV9), B (ZV10) | C после A и B | ZV6 → ZV9 |

D — общий слой метрик: он стартует до A/B/C и не мержится отдельно от
baseline-прогона.

Repair-lane идёт параллельно всем трём дням и не занимает основной слот.
Заблокированная задача уходит в неё, main-lane сразу берёт следующую; watchdog
45 минут переключает и пишет строку в лог.

Общий критический путь программы: **ZV1 → ZV2 → ZV6 → ZV9**. `ZV10` идёт
параллельно `ZV9` и не удлиняет путь, если `ZV1` закрыт в день 1.

Нельзя параллелить:

- `ZV6` и `ZV9` — оба меняют `artefact.json` и `marker_panel`/`marker_solved`;
- `ZV10` и любой шаг, который правит `dev/check.R` (один файл — один
  владелец);
- `docs/INDEX.md` и `NEWS.md` — только поток C дня 3.

## 6. Критерии провала

### Провал дня

1. Любой гейт дня красный на конец дня.
2. Сценарий дня не запускается без сети, без коммиченной фикстуры или без
   интерактивной сессии.
3. Сценарий проходит только через `skip_if_no_*()` и не проверяет ни одного
   контрактного шага.
4. Пользовательский шаг требует `$`, `[[` или ручного вытаскивания колонки.
5. Новый экспорт не имеет строки в `docs/user-api-surface.csv` или владельца
   в ADR/ZV.
6. Вердикт на золотом наборе изменился при том же входе.
7. Baseline снят после первой правки кода, или хотя бы один прогон не оставил
   JSONL.
8. В JSONL есть `prompt`, `content`, `sequence`, метка цели или путь; схема
   отвергла бы это, а гейт пропустил.
9. p95 стадии выше baseline, стоимость маршрута J1–J7 выросла, или выход
   повторного прогона не байт-идентичен (канонический срез метрик — тоже).
10. В очереди меньше трёх следующих задач; 45 минут без коммита и без строки
    в логе; repair-lane занял единственный основной слот; quarantine без
    вопроса человеку; тест ослаблен, удалён или пропущен без quarantine.

### Провал программы

1. J1–J7 не все зелёные к концу дня 3.
2. `artefact@2` не воспроизводится байт-в-байт при фиксированном
   `SOURCE_DATE_EPOCH`.
3. MCP parity-гейт не ловит хотя бы один из шести классов дрейфа (имена,
   аргументы, границы, аннотации, классы CSV, покрытие сценариев).
4. J4 заявляет 16 Гб-замер без записи в
   `docs/decisions/0001-16gb-fixpur.md`; фикстура выдаётся за операторский
   прогон.
5. `panel$experimental` снят до зелёного J3.
6. Закрытый ZV не имеет теста и гейта; закрытие сделано ссылкой на ADR.
7. `dev/check.R --full`, `check-user-api.R` и `check-mcp-parity.R` не все
   зелёные на одном коммите.
8. Нет итогового `data/metrics/metrics-<date>.md` с p50/p95, стоимостью на
   маршрут, долей провалов и дельтой к baseline; или baseline снят не на
   `main` до первой правки.
9. Хотя бы один маршрут J1–J7 не имеет ни одного JSONL-прогона за три дня.
10. Программа стояла 45 минут и больше без watchdog-строки; блокер закрыт
    ослаблением теста, выдуманным данным или необратимым действием без
    человека.

### Срез объёма (не провал, если объявлен)

- День 1: первым `ZV3`, затем `ZV4`, затем `ZV5`.
- День 2: `ZV7` можно отложить, если J5 остаётся красным по данным, а не по
  коду; `ZV6` и `ZV8` — нет.

## 9. Риски и как их снимать

| Риск | Симптом | Снятие |
| ---- | ------- | ------ |
| Нет OligoArrayAux/bowtie | J1/J3/J5/J6 только skip | контрактный шаг без движка всё равно проверяется; движок — операторская установка, не заглушка |
| 16 ГБ fixpur недоступен | J4 не доказывает масштаб | три сборки + synthetic 250 Мб + decision 0001; 16 ГБ — операторский прогон |
| `artefact@2` ломает id | старые файлы не читаются | `marker_artefact_read()` с миграционной заметкой; `NEWS.md` |
| `check-user-api.R` статичен | сценарий зелёный в графе, красный в R | пара: статическая проверка + `test-scenario-jN.R` |
| MCP parity слишком широкая | гейт падает на каждом новом поле | шесть классов дрейфа, названных в ADR 0011; additive-поля не ломают |
| Три дня не хватает | ZV3/ZV4/ZV5 в работе | срез по правилу; гейты и J1/J2/J3/J6/J7 не двигаются |
| Метрики шумят | p95 скачет на малых выборках | `n >= 20` и nearest-rank; иначе `not_run` с числом сэмплов |
| JSONL разрастается | файлы на каждый прогон | только числа; один файл на прогон; ротация по дате, содержимое запрещено |
| Блокер останавливает lane | нет коммита 45 минут | watchdog, repair-lane, 3 следующие задачи; quarantine с вопросом |
| Quarantine копится | доля > 30% | разбор человеком и revisit-дата; цифра в отчёте, не тишина |
