# 0007 — Module seams and the MCP runtime contract

- Status: proposed
- Date: 2026-11-26
- Supersedes: none

## Context

The package is 88 files and 38,653 lines under `R/`. Four files dominate:
`marker_specificity.R` (2,487), `marker_plots.R` (1,620),
`marker_assemble.R` (1,571) and `marker_criteria.R` (1,505). The same small
patterns are copied across them and across the rest of the tree:

- **Required-column guard.** `setdiff(need, names(x))` followed by an abort
  appears at 30 call sites in 21 files today; the 2026-11-26 proposal counted 11.
  `R/marker_contracts.R` already holds `marker_contract()` and three
  design-by-contract helpers, but no shared column guard.
- **Message wrapper.** `cli::cli_abort(gettext(...))` appears in 49 files and
  216 calls; 66 files use `gettext()` in some form. The proposal counted 54
  files. `po/README.md` records why the wrap is manual: `potools` does not see
  `cli`/`rlang` calls, and one literal must be one `msgid`.
- **S3 delegators.** 30 `print.<class>`, 17 `plot.<class>` and 16
  `marker_map_spec.<class>` methods exist. Most repeat a header, a table and a
  few labels. There is no shared `"marker"` superclass, so each class needs its
  own method today.
- **MCP.** `inst/mcp/tools.R` holds 38 tool specs, each with an `inputSchema`.
  `mcp_call()` looks up the spec and calls `spec$handler(args)` directly. It does
  not validate `args` against the schema. An unknown tool returns a text
  `isError`, not a JSON-RPC error. `tools/list` emits only `name`, `title`,
  `description` and `inputSchema`; there is no read-only or mutating annotation.
  `inst/mcp/schema.json` is generated by `dev/mcp-schema.R` and drift-tested by
  `tests/testthat/test-mcp.R`, but nothing reads it at run time (ADR 0004,
  amendment 2026-11-26). Its per-tool `inputSchema` entry currently asserts only
  `type: object`, so the file describes the `tools/list` shape, not the
  arguments of a call. The server reports protocol version `2024-11-05`.
- **Dependency seams.** `DECIPHER` is used in 14 files (alignment and PCR
  efficiency), `TmCalculator` in 9 (the Tm engine and its constants), `ggforce`
  in one `facet_zoom()` call, `forcats` in four calls in two files, `vctrs` in
  one file, `digest` in three calls, `processx` in three files. `NAMESPACE` has
  205 exports.

`dev/check.R` is the local gate (roxygen, styler, lintr, criterion fixtures,
docs/artifacts, examples, spelling, optional full tests). It does not yet measure
file length, export count, MCP argument validation coverage or a per-tool
contract.

## Decision

### 1. One column guard, one message wrapper

`R/marker_contracts.R` gains:

```r
need_cols(x, cols, arg = "x", call = rlang::caller_env())
```

It calls `marker_contract()` and aborts with
`class = c("tidymarkers_contract_error", "tidymarkers_missing_columns")`,
naming `arg` and the missing columns. The 30 call sites become one line each;
the message is identical at every seam. `marker_contract()` stays the only
place that decides whether contracts are enabled.

`R/marker_i18n.R` gains:

```r
abort_msg(message, ..., class = NULL, call = rlang::caller_env())
```

`message` is one literal, `...` are named bullets, and each is passed through
`gettext()` exactly once before `cli::cli_abort()`. The wrapper preserves
`cli`'s bullet names and the condition class. `po/README.md` gains `abort_msg`
as a custom translation function for `potools::po_extract()`, so the 216 call
sites keep their `msgid`s. If the extractor cannot see the wrapper, the gate
fails; the fallback is not to leave 216 `gettext()` calls in place silently.

### 2. Three registries, one superclass

`R/marker_result_registry.R` holds:

- `marker_print_registry()` — class -> print formatter;
- `marker_plot_registry()` — class -> plot builder;
- `marker_map_spec_registry()` — class -> map specification.

List-based result objects that have a print or plot method gain `"marker"` as
their **last** class. Existing `inherits(x, "marker_assay")` and `class(x)[1]`
stay unchanged. One
`print.marker()`, one `plot.marker()` and one `marker_map_spec.marker()` dispatch
through the registry on `class(x)[1]`. The 30 print and 17 plot methods are
deleted; the 16 `marker_map_spec` methods are deleted. A class that genuinely
needs a different method keeps it and is registered as `NULL`, so the registry
does not hide a one-off.

Structures that already carry their own typed class (`marker_criteria`, a
tibble subclass, and `marker_trace`, a list) do not gain `"marker"`; they keep
their existing class and print path.

### 3. Split the four god files

No behaviour change, no new export:

| File                  | Lines | Split into                                                                 |
| --------------------- | ----: | -------------------------------------------------------------------------- |
| `marker_specificity.R` | 2,487 | `marker_specificity_seed.R`, `marker_specificity_index.R`, `marker_specificity_cache.R` |
| `marker_plots.R`       | 1,620 | `marker_plots_ideogram.R`, `marker_plots_diagram.R`, `marker_plots_layers.R` |
| `marker_assemble.R`    | 1,571 | `marker_assemble_as.R`, `marker_assemble_com.R`, `marker_assemble_contract.R` |
| `marker_criteria.R`    | 1,505 | `marker_criteria_registry.R`, `marker_criteria_table.R`, `marker_criteria_evidence.R` |

Each resulting file stays under 1,200 lines. Roxygen `@family` and `@method`
tags move with their functions; `NAMESPACE` and `man/` must be identical after
`roxygen2::roxygenise()`.

### 4. MCP validates arguments and states side effects

`inst/mcp/tools.R` gains `mcp_validate_args(args, schema, path = "arguments")`,
a recursive validator for the JSON Schema subset the registry actually uses:
`type` (`object`, `array`, `string`, `number`, `integer`, `boolean`, `null`),
`required`, `properties`, `enum`, `minimum`, `maximum`, `minItems`, `maxItems`,
`pattern`, and `additionalProperties`. Object schemas default to
`additionalProperties = FALSE`: a handler must not receive an argument it
silently ignores.

`mcp_call()` becomes:

- unknown tool -> JSON-RPC `-32602`, `data = list(tool, path, expected, got)`;
- invalid arguments -> JSON-RPC `-32602`, `data = list(tool, path, expected, got)`;
- handler error -> `result$isError = TRUE` with the message (a tool execution
  error, not a protocol error);
- success -> `content` plus `structuredContent`, as today.

`tools/list` gains `annotations` from `mcp_tool_annotations()`:
`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint = FALSE`.
The rule is explicit: read-only means no caller-visible file, no registry
mutation and no network; design calls that only use the session temp directory
are read-only. `marker_technology` is the mutating tool (`readOnlyHint = FALSE`,
`destructiveHint = TRUE`); every other tool is read-only. The 38-entry table is
the source of truth, and `tools/list` returns it for every tool.

The server keeps `protocolVersion = "2024-11-05"`. `annotations` is an additive
field that older clients ignore; a later protocol bump can adopt it as the
standard object without a second registry.

**The schema file is completed, then read by tests, not by the server.**
`dev/mcp-schema.R` now publishes each tool's full `inputSchema` (properties,
required list and enums), not just `type: object`, so the file can validate a
call. The server still validates against `spec$inputSchema`, the object the file
is generated from; parsing the serialised copy at run time would create a second
source of truth. `test-mcp-validation.R` proves the published per-tool schema
and the runtime schema are the same object, and `dev/mcp-schema.R --check` fails
on drift. This keeps ADR 0004's boundary: `inst/mcp/schema.json` is a contract
artefact, not a runtime dependency, and there is still one definition of a
tool's input.

### 5. Dependency and runtime seams

- **Keep `DECIPHER`** — 14 files, alignment and `CalculateEfficiencyPCR()`.
- **Keep `TmCalculator`** — 9 files, the nearest-neighbour engine; the internal
  dG parameters intentionally mirror it.
- **Keep `ggforce`** — one call site, but it is the zoomed panel feature, not a
  convenience. Drop it only if `facet_zoom()` is removed.
- **Drop `forcats`** — four calls in two files. `fct()`, `fct_rev()` and
  `fct_lump_n()` become base `factor()` plus one internal `lump_top_n()`
  helper. `forcats` leaves `DESCRIPTION` and `NAMESPACE`.
- **Keep `vctrs`** — the `marker_criteria` table class already has
  `vec_restore`, `vec_ptype2`, `vec_cast` and `vec_ptype_abbr`
  (`R/marker_criteria.R`). No second `criterion` row class is introduced without
  a caller; the gate adds `vec_c()`/`rbind()` tests for the existing class.
- **`digest` -> `hash_object()`/`hash_file()`** in `R/marker_hash.R`. The three
  direct calls become one seam; `digest` stays the implementation.
- **`processx` for external processes.** `R/marker_exec.R` gains
  `run_external(cmd, args, timeout = )` on `processx::run()` with
  `error_on_status = FALSE` and a classed `tidymarkers_timeout`. Bowtie, BLAST
  and the other binaries the package owns go through it. `Rbowtie` and `rBLAST`
  remain the parsers; where their wrapper does not expose the process, the
  timeout is a named limit in the manifest, not an unstated assumption.

## Gates

1. `Rscript dev/check.R` is green: roxygen/`man/` sync, styler, lintr, criterion
   fixtures, docs/artifacts, examples and spelling.
2. Export count does not grow: `NAMESPACE` has at most 205 `export` lines. The
   registries and the splits add no user-facing function.
3. No file under `R/` exceeds 1,200 lines. The check is a new step in
   `dev/check.R` (a `wc -l` over `R/*.R`), so the limit is enforced by the gate,
   not by review.
4. `tests/testthat/test-mcp-validation.R` covers every one of the 38 tools: one
   valid minimal call and one invalid argument per tool, asserting `-32602` and
   the `data$path`. The table length must equal `length(mcp_tool_specs())`.
5. `dev/mcp-schema.R --check` is green; `inst/mcp/schema.json` publishes the
   full per-tool input schema (properties, required, enums), and the validation
   corpus agrees with `mcp_tool_specs()` for the same 38 tools.
6. `print()`, `plot()` and `marker_map_spec()` snapshots are identical before
   and after the registry change for all classes that had a method. `class()`
   gains `"marker"` as the last element; this is documented in `NEWS.md`.
7. `potools::po_extract()` still finds every message, including the
   `abort_msg()` literals; a `LANGUAGE=ru` smoke test covers three aborts.
8. `grep -r forcats R` is empty; `R CMD check` reports no unused import.
9. A stub executable that sleeps for 60 s is killed by `run_external()` at a
   1 s timeout; the condition class is `tidymarkers_timeout` and no child
   process survives.
10. `test-criteria.R` proves `vec_c()`, `rbind()` and subsetting keep
    `marker_criteria`; a plain `tbl_df` is downgraded, not upgraded.

## Consequences

- One column guard and one message wrapper replace 30 and 216 duplicated
  bodies; a new call site cannot invent its own wording.
- 47 print/plot methods and 16 map-spec methods collapse to three dispatchers
  and three registries. The method count in `NAMESPACE` falls; the S3 surface
  for callers stays `print()`/`plot()`.
- `class(x)` gains `"marker"` as its last element. Code that compares
  `identical(class(x), "marker_assay")` breaks; `inherits()` and `[1]` do not.
  This is a breaking change and goes to `NEWS.md`.
- MCP clients that send unknown arguments now get `-32602` instead of a handler
  that ignores them. That is the point; it is still a behaviour change.
- `annotations` is additive on protocol `2024-11-05`; a client that does not
  know it ignores it.
- `forcats` leaves the dependency set; `ggforce`, `DECIPHER`, `TmCalculator`
  and `vctrs` stay with a named reason.
- `hash_object()` and `run_external()` become the only places a hash algorithm
  or a process timeout is chosen.
- The four god files disappear; `git log`/`blame` on a moved function needs
  `git log --follow`, which is the cost of the split.

## Alternatives

- **Leave the guards and messages duplicated.** Rejected: the 30 guards already
  differ in wording, and the 216 aborts already differ in class and call.
- **Use `checkmate`/`assertthat` for the guard.** Rejected: `R/marker_contracts.R`
  exists for this, and a new dependency needs a call site the package does not
  have (ADR 0001's rule).
- **Keep one method per class and only share helpers.** Rejected: the duplicated
  bodies are the problem; helpers leave 63 methods to maintain.
- **Make the server read `inst/mcp/schema.json` at runtime.** Rejected: it is a
  serialised copy of `mcp_tool_specs()`, and loading it would create a second
  source of truth to keep in sync. The drift test already makes the file a gate.
- **Bump `protocolVersion` to 2025-03-26 now.** Rejected: it can break a client
  that negotiated `2024-11-05`; the annotations field is additive, so the bump
  is a separate decision.
- **Add a `criterion` row class.** Rejected without a caller: the table class
  already carries the cast/ptype contract; a row class would duplicate vctrs
  methods for no consumer.

## Revisit trigger

A second consumer of the MCP surface that needs the annotations as a standard
protocol field, or a caller that needs `criterion` rows to survive `vec_c()` as
a distinct type. Also revisit the split if a file grows past 1,200 lines again,
and the timeout contract if `Rbowtie`/`rBLAST` start exposing their processes.
