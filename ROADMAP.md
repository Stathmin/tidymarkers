> Внутренний документ разработки: в собранный пакет не входит (`.Rbuildignore`).
> Пользовательская документация — `README.md` и виньетки.

Только незакрытое.
История изменений — в `NEWS.md`.

Обозначения: `[ ]` очередь · `[~]` частично · `[x]` сделано · `[—]` проверено и
**отложено** (с причиной) · `[!]` проверено и **опровергнуто**.

**Формат пункта.** Каждый открытый пункт отвечает на четыре вопроса:

- **правка** — что именно менять и где (файл и функция, а не тема);
- **проверка** — чем закрывается (тест-файл, id в `dev/check-criteria.R`, артефакт);
- **блокер** — что не даёт начать, и чем он снимается;
- **следствие** — что меняется, если пункт НЕ делать (почему он вообще стоит).

Пункт без одного из четырёх — не готов к работе и остаётся в своей секции как
описание, а не в очереди.

> **О провенансе.** Ниже отдельно помечено, что **открыто прочитано**, а что
> известно только по идентификатору. Правило то же, что в коде: **DOI/название —
> это провенанс, а не доказательство.** Число попадает в `inst/extdata/` только
> если оно прочитано из скачанного файла, и у него есть скрипт
> `data-raw/<paper>.R`, который утверждает его против собственных итогов статьи и
> падает при расхождении. Где такого утверждения построить нельзя — файл не
> пишется, и причина записывается.

## Приоритет

Наука раньше архитектуры: `Z7` (намеренные вторые мисматричи) → `Z8`
(калибровка); `ZA6` шаги 1–4 — контракты данных, шаги 5–8 — после `Z8`.
Дисциплина «рефакторинг не сдвигает вердикт»: шаг принимается только с
неизменными вердиктами на золотом наборе.

## Решения

Все решения `Q1`/`Q2` приняты; каждое — `*.decision.md` в `data-raw/proposed/`
(статус, правка, тест). `.proposal.md` — запись доказательств, после решения не
правится. Пока решение не принято, артефакт говорит «данных нет», а не «данные
против».

### §V. Модели считывания (readout simulation)

- [~] **HRM — модель плавления; dPCR — пуассоновское разбиение; CRISPR-Dx —
  коллатеральное расщепление; ARMS/CAPS/indel_size/SSR — виртуальный гель;
  LAMP/RPA — изотермическая кинетика.** Состояние в коде: `marker_readout()`
  честно возвращает `simulated = FALSE` с причиной для каждой химии
  (`R/marker_readout.R`, таблица `notes`), единственное исключение —
  гидролизная проба.
    - **dPCR** — единственный пункт с данными: `mismatch`-часть готова, но
      пуассоновская модель проверяется **аналитически**, не подгонкой
      (`Z8.6`).
    - **HRM** — ближайший кандидат: есть `dTm` по трём наборам (см. `Z9.2`).
    - **LAMP/RPA** — кинетику из имеющихся источников строить нельзя (`Q1`).
    - **Литература 2026-11-03 (предложения, `data-raw/proposed/`):** HRM — 28
      строк (частично: нет Mg/соли); dPCR — достаточно; CRISPR-Dx — 0; виртуальный
      гель — 0; LAMP/RPA — 24 строки из Zhang 2026 NAR
      (`doi:10.1093/nar/gkaf1378`, `PMC12774662`), частично (`time_to_positive`
      не задан). Критерии и DAG не менялись.
    - Правка начинается только тогда, когда есть набор «условия → исход», который
      модель обязана воспроизвести; иначе `simulated = TRUE` станет ложью.
      Проверка — тот же набор, что читает `test-readout-physics.R`.
    - **Поиск 2026-10-29 (наборы «условия → исход»):** HRM —
      `readout_hrm_diatom2025.csv` (28 ампликонов, измеренный Tm + dH/dS, но нет
      Mg и нет соли → **partial**, `simulated` остаётся FALSE); LAMP —
      `readout_lamp_erysiphe2026.csv` (Tp × температура и × десятикратное
      разведение, но `copies_per_reaction` = NA → **partial**, `Q1` **не
      закрыт**); dPCR — Пуассон **достаточен** (`dong2015` + `mps2024`, третьего
      набора нет); CRISPR-Dx — **нет** (кинетика в платном supplement);
      виртуальный гель — **нет** (никто не печатает bp→мм с % геля, вольтажом и
      временем). Три «нет» — это отсутствие в открытом доступе по выполненному
      поиску, не доказательство несуществования (см. `v-readout-conditions.md`).
    - **Поиск 2026-11-03 (раунд 2):** CRISPR-Dx — частично: Nalefski 2024
      (`PMC11077072`) печатает kcat/KM и константы активации в Tables 1–2

      не ряд «концентрация цели → доля расщеплённого во времени». HRM (Mg/соль),
      виртуальный гель, LAMP/RPA (`copies_per_reaction`) — не найдено в открытом
      доступе. `simulated` теперь TRUE только у dPCR (Пуассон); у остальных
      четырёх химий — FALSE.
    - **Сделано 2026-11-03:** dPCR-Пуассон заведён в `R/marker_readout.R`

      «hydrolysis-probe discrimination + Poisson droplet partitioning» и

## ZA. Целевые интерфейсы и швы (codebase-design)

Это план перестройки **модулей и швов**, а не список функций. Принцип:
табличные данные — `tibble`/`vctrs`; поведение — S3-generic; граф —
`tidygraph`; рисование — грамматика `ggplot2`; внешний движок — adapter с
`capabilities()`. Не тащить `R6`/`data.table`; не превращать поведение в
data-frame только ради «tidy».

**Состояние: шаги 1–4 частично сделаны.** `Evaluation` (единый
`marker_evaluation_table()` + статус `pass|fail|unknown|not_applicable`),
`MarkerContext`/`ReactionConditions`/`Engines` (`marker_run_context()`,
`marker_engines()`) и реестр критериев (`criterion_spec()`) существуют. `Scheme`
как S3-адаптер — нет: вызывается `design_<m>_marker()`. Шаги 5–8 заперты на `Z8`.
Наука (`Z`, `Z7`) стоит выше всего этого (см. «Приоритет»).

### ZA1. Целевой путь вызова

```r
context <- marker_context(
  genome, variants = NULL, population = NULL,
  conditions = reaction_conditions("pcr"), engines = marker_engines()
)
scheme <- marker_scheme("caps")
m  <- scheme$design(snp, context)
ev <- scheme$evaluate(m, context)
tr <- scheme$tracks(m, context)
dc <- scheme$decision()
ro <- scheme$readout(m, context)
```

Сегодня: `marker_scheme("caps")` работает, но возвращает строку реестра, а не
объект с `$design()`; вызов идёт через `design_caps_marker(genome, snp)`.

### ZA5. Что не делать tidy/ggplot

- `Scheme` и `Engines` — поведение, S3-generic, не data-frame.
- `DecisionSchema` — графовые данные + state; рисование отдельным adapter.

- Не вводить seam для одного adapter (deletion test): если удаление модуля
  просто возвращает сложность одному caller, это pass-through.

### ZP2. Merge order

1. ~~`wip/roadmap-base` → `main`~~ — сделано (`8639434`).
2. Одна ветка из таблицы выше за раз; база — `main`.
3. После каждого merge: `Rscript dev/check.R --no-render`; полный gate — в
   integration worktree. Конфликты решать в integration worktree, не в агентских.
4. Vignette-ветки — последними.
5. Удалять ветку только после merge и только после `git worktree list`;
   `.tools` в новом worktree не симлинк, а отсутствующий каталог — путь задаётся
   `PATH`/`UNAFOLDDAT`, и это единственное, что переезжает между worktree.
6. **Не squash: golden-тесты и `docs/artifacts.yml` привязаны к коммитам** —
   сквош меняет хеши, на которые ссылается манифест, и делает 20 SVG stale.

### ZP4. Anti-patterns

- N branches in one clone without worktrees.
