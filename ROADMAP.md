# tidymarkers — roadmap (открытая работа)

> Внутренний документ разработки: в собранный пакет не входит (`.Rbuildignore`).
> Пользовательская документация — `README.md` и виньетки.

Только незакрытое; история изменений — `NEWS.md`.

Обозначения: `[ ]` очередь · `[~]` частично · `[x]` сделано · `[—]` проверено
и **отложено** (с причиной) · `[!]` проверено и **опровергнуто**.

**Формат открытого пункта:** **правка** (файл и функция) · **проверка** (тест, id
в `dev/check-criteria.R`, артефакт) · **блокер** (что не даёт начать и чем
снимается) · **следствие** (что меняется, если пункт не делать). Пункт без
одного из четырёх остаётся в секции как описание, а не в очереди.

**О провенансе.** DOI/название — это провенанс, а не доказательство. Число
попадает в `inst/extdata/`, только если оно прочитано из скачанного файла и у
него есть `data-raw/<paper>.R`, который утверждает его против итогов статьи и
падает при расхождении. Где такого утверждения построить нельзя — файл не
пишется, причина записывается.

## Очередь

Открытая работа ведётся по секциям ниже, каждая с чекбоксом; `Y`/`YP` — тоже
очередь (пункты `[ ]`/`[~]` рабочие, не идеи). История — `NEWS.md`, провенанс
источников — `inst/extdata/science_ledger.csv`.

Порядок: `## Известные дефекты` (меняют вердикт при том же входе) → `ZX1`/`ZX2`
(масштаб: индекс, параллель по локусам) → научная очередь `Z7` → `Z8`.
Горизонт и то, что сознательно не делается, — `ZX3`/`ZX4`; там же единственный
дом для планов «документация ↔ код» (граф). Категория-определяющая
инфраструктура — `ZY`: очередь `ZY1`–`ZY20`, у каждого пункта есть четыре поля;
внутри неё сначала разблокированное, потом внешне заблокированное.

## Приоритет

Наука раньше архитектуры: `Z7` (намеренные вторые мисматричи) → `Z8`
(калибровка); `ZA6` шаги 1–4 — контракты данных, шаги 5–8 — после `Z8`.
Дефекты `D1`–`D5` — раньше новой науки: они меняют вердикт на том же входе.
Дисциплина «рефакторинг не сдвигает вердикт»: шаг принимается только с
неизменными вердиктами на золотом наборе. `ZY` — отдельная очередь: приоритет
внутри неё задаёт порядок пунктов, а не шкала `P0`–`P2` из `Z`; гейты `ZX4`
(Rust после замера R-адаптера) и `Z8` (калибровка) действуют и там.

## Остатки в закрытых пунктах

Закрытый пункт (`[x]`) может оставить живой остаток. Здесь он развёрнут в
свой пункт с полями по формату выше; родитель ссылается сюда подпунктом.

**Когда остаток обязателен.** Если в тексте закрытого пункта названа
отложенная часть («кроме», «пока», «только для», «не покрыт»), пункт обязан
ссылаться сюда: (`## Остатки в закрытых пунктах`, №N). «Закрыто, кроме X» без
ссылки — дефект roadmap, а не заметка. Тот же дефект есть у закрытого пункта,
который внутри оставил открытый (`[ ]`) или частичный (`[~]`) подпункт: это
многострочная форма «сделано, кроме».

Механика: `dev/audit-remainders.R --check` в гейте (`dev/check.R`, шаг
`docs/artifacts`) даёт список внимания, а не доказательство. Он ловит оба случая
(слово-отсрочка в теле пункта и открытый подпункт) и принимает ссылки трёх видов:
на этот раздел, на `Запаркованные остатки`, на номер `№N` или раздел `§Z…`.
Слабое место остаётся: честная заметка об объёме читается как отсрочка, а
отсрочка без отсрочного слова — нет. Поэтому сверка в каждой волне закрытия
ручная, а гейт ловит забытые ссылки, а не смысл.

  принять: один геном на сессию. При нарушении — ключ по хешу всей
  последовательности.
- [—] **Кеш генома — на объект, а не на сессию.** `R/marker_genome.R`: каждая
  `marker_genome` держит свою хромосому в RAM, две геномные переменные кеш
  не делят, `options(tidymarkers.genome_cache = FALSE)` должен быть
  выставлен до сборки объекта. Названо в `?marker_genome`; менять — только
  если появится второй геном в одном прогоне.

## ZA. Целевые интерфейсы и швы (codebase-design)

План перестройки **модулей и швов**, не список функций. Принцип: табличные
данные — `tibble`/`vctrs`; поведение — S3-generic; граф — `tidygraph`; рисование
— грамматика `ggplot2`; внешний движок — adapter с `capabilities()`. Не тащить
`R6`/`data.table`.

**Состояние:** шаги 1–4 частично. `Evaluation`, `MarkerContext`/
`ReactionConditions`/`Engines`, `criterion_spec()` есть; `Scheme` — адаптер
(`marker_scheme_adapter()`, `scheme_designer()`). Шаги 5–8 заперты на `Z8`.
Наука (`Z`, `Z7`) выше всего этого.

### ZA1. Целевой путь вызова

```r
context <- marker_context(
  genome, variants = NULL, population = NULL,
  conditions = reaction_conditions("pcr"), engines = marker_engines()
)
scheme <- marker_scheme("caps")
m  <- scheme$design(snp, context)
ev <- scheme$evaluate(m, context)
tr <- scheme$tracks(m, context)
dc <- scheme$decision()
ro <- scheme$readout(m, context)
```

Сегодня `marker_scheme("caps")` возвращает строку реестра, а не объект с
`$design()`; вызов идёт через `design_caps_marker(genome, snp)`.

### ZP2. Merge order

Одна ветка из таблицы за раз, база — `main`; после каждого merge —
`Rscript dev/check.R --no-render`, полный gate — в integration worktree;
конфликты решать там, не в агентских. Vignette-ветки — последними. Удалять
ветку после merge и `git worktree list`. **Не squash:** golden-тесты и
`docs/artifacts.yml` привязаны к коммитам, сквош делает 20 SVG stale.

### ZP3. Agent brief

```text
Worktree: /abs/path/tidymarkers-<slug>
Branch: feat/<slug> (already checked out; do NOT checkout elsewhere)
Owns: <paths>
Forbidden: <paths>
Env (every shell call):
  PATH=/opt/R-4.6.1/bin:<clone>/.tools/bin:$PATH
  UNAFOLDDAT=<clone>/.tools/share/oligoarrayaux
  R_LIBS_SITE=/opt/R-4.6.1/lib/R/library
  (R_LIBS must NOT be set — system-R `rlang.so` breaks the load)
  load with pkgload::load_all(".")
Tests: Rscript dev/test.R <filter>; Rscript dev/check.R --no-render
Never run the full suite while iterating (8+ min): test_dir(filter=...) or dev/test.R.
Commit only on feat/<slug>; verify git branch --show-current before commit.
Commit message via `git commit -F file` — never -m with backticks or $().
```

### ZP4. Anti-patterns

N веток в одном clone без worktree; worktree от stale `HEAD` при грязном дереве;
два агента в одной виньетке/helper; параллельная dPCR-калибровка до Tm-движка;
merge без gate; удаление worktree до merge; новые worktree от
`wip/roadmap-base` (ветки нет); squash-merge.

      и фальсификация `ZY24` меряют на наборах с заранее установленным вердиктом;
      `ZY24` пишет `baseline:corpus` как `not_run`, потому что
      `marker_record_outcome()` не хранит исходов. Cell Genomics 2026 называет
      валидацию узким местом агентных пайплайнов — именно этого корпуса и нет.
      правка: `R/marker_outcomes.R` уже пишет исход в `outcomes.csv` каталога
      артефакта (`marker_record_outcome()`) и читает его обратно (`marker_outcomes()`)
      колонками `id` / `recorded` / `target` / `result` / `notes` / `calibrated`;
      запись с нерезолвящимся артефактом отклоняется с причиной. Остаётся то, чего
      нет: чтение **поперёк** артефактов — один корпус (`marker_outcome_corpus()`),
      который обходит каталоги и сводит строки, сохраняя `artefact_id` в каждой.
      проверка: `tests/testthat/test-z8-outcomes.R` и `test-contracts.R` уже держат
      запись-чтение, отказ без артефакта и cause chain; новый корпус-ридер получает
      тест на двух артефактах — строки не смешиваются и `id` не теряется.
      блокер: реальные исходы даёт только лаборатория; демонстрация
      ограничивается синтетическими записями, и это сказано в тесте.
      следствие: `baseline:corpus` остаётся `not_run`, а модель успеха (`ZY29`)
      не на чем обучать.
- [ ] **`ZY27` Передача исходов без сети (data-sovereign export).** Methodology §6
      обещает, что агрегат не равен анонимизации, и ссылается на модель Data
      Trustee (Theoretical and Applied Genetics 2025); rMAP 2.0
      (Bioinformatics Advances 2026) показывает, что офлайн-прогон — ожидаемое
      требование. Экспорта, который отдают попечителю без потери провенанса, нет:
      crate из `ZY23` несёт прогон, а не строки исходов.
      правка: новый `R/marker_export_outcomes.R` —
      `marker_export_outcomes(corpus, dir, trustee = NULL)` пишет RO-Crate, где
      каждая строка исхода — `Entity` со ссылкой на `artefact_id`, hashed inputs
      и схему; идентификатор участника заменяется псевдонимом, маппинг остаётся
      у владельца; сетевых вызовов нет.
      проверка: `tests/testthat/test-outcomes-crate.R` — crate читается обратно
      тем же `marker_import_rocrate()`; псевдонимы участников не совпадают с
      исходными значениями; в crate нет абсолютных путей.
      блокер: официального валидатора RO-Crate в дереве нет (как в `ZY23`),
      проверка структурная.
      следствие: данные остаются внутри одной лаборатории, а федеративная
      передача в methodology — проза без артефакта.
- [x] **`ZY28` Гейт лицензий зависимостей в CI.** `ZY18` называет дефект
      инварианта: шага проверки лицензий в `.github/workflows/` нет, то есть
      «commons licensing» — обещание, а не выполненное условие.
      правка: новый `dev/check-licenses.R` читает `DESCRIPTION` и лицензии
      установленных зависимостей, сверяет их с `dev/allowed-licenses.txt` (строка
      на лицензию с причиной) и падает на неизвестной или запрещённой; шаг
      вызывается из `.github/workflows/R-CMD-check.yaml` и из `dev/check.R`.
      проверка: `Rscript dev/check-licenses.R --self-test` — классификатор
      прогоняется по литералам (разрешённая, запрещённая, двойная, неизвестная и
      пустая лицензия дают ожидаемый вердикт), а `Rscript dev/check-licenses.R`
      воспроизводит тот же вердикт на установленном наборе.
      блокер: нет.
      следствие (до правки): «commons licensing» был обещанием — зависимость с
      несовместимой лицензией проходила CI молча.

      двойное лицензирование как отказ) и печатает счётчики по вердиктам;

      списки живут рядом с классификатором, а его проверка — `--self-test` в том же
      скрипте, без второго файла на то же утверждение. Шаг стоит в
      `.github/workflows/R-CMD-check.yaml` и вызывается из `dev/check.R`, так что
      локальный гейт и CI меряют одно.

      раздел `## Success model`.
      проверка: ниже названного порога записей скрипт печатает `not_run` с
      причиной, а не число; выше — AUC воспроизводится между прогонами.
      блокер: зависит от `ZY26`; без реальных исходов обучать нечего. Начинать
      только после того, как `marker_outcome_corpus()` даст записи из двух

      следствие: многоосевой вердикт остаётся аргументом, а не измерением.

### ZY. Горизонт за очередью

Не пункты и не гейт — направления, которые станут пунктами, когда появится
названный вход:

- **Мультиплекс одной химии на популяции.** `marker_plan()` собирает пары, а
  one-pot-оценка уже есть; следующий шаг — план на phased haplotypes с
  per-target tolerance для не-арабидопсисных геномов, когда `ZY1` даст панель.
- **Оракулы структуры как гейт, а не cross-check.** UNAFold/NUPACK/MELTING
  сегодня проверяют пакет; превратить их в правило можно только с закреплённым
  порогом и строкой в `VALIDATION.md`, иначе это шум (расширение `ZY20`).
- **Внешняя обратная связь.** `marker_record_outcome()` существует, но записей
  нет; любой горизонт дальше `ZY26` упирается в это, а не в код.

### ZY18. Инварианты, не подлежащие ослаблению

Это контекст, а не пункты: каждый `ZYn` выше обязан их соблюдать. Где инвариант
уже покрыт машинной проверкой — назван тест.

- **Fabrication refusal:** ни одна функция не возвращает invented data при
  отсутствии provenance. `missing_api_key` / `not_configured` / explicit refusal
  с cause chain — обязательны.
- **Honest limits:** measured и predicted различаются явно и assert'ятся как
  tested behaviour, не corrected away (`test-tm-mm2020.R` — 16.9 °C).
- **Policy as data:** decision schema читается из тех же констант, что
  исполняется; graph не может drift от кода (`marker_decision_schema()`).
- **Commons licensing:** MIT, без weaponized license additions. Внешние
  dependencies должны проверяться CI на forbidden licenses — **этой проверки в
  CI сегодня нет** (в `.github/workflows/` такого шага нет); это дефект
  инварианта, а не выполненное обещание.
- **Attribution:** каждый rule в коде связан с конкретным extract'ом из
  конкретного source; test не может claim extract, который не читает
  (`test-science-ledger.R`).
- **Reproducibility:** external data никогда не ships с пакетом; всё
  downloadable или cached через `marker_cache_dir()`.
- **Feature-level graceful degradation Suggests:** missing optional dep
  деградирует одну feature, не ломает load.

### ZY19. Единицы прогресса

Контекст для оценки движения, не пункты и не гейт; первые две читаются с
артефактов и реестра, остальные — из истории и CI.

- Decision trace coverage (доля production designs с полным RDS artefact).
- Criterion registry evidence rung distribution (стабильный или растущий
  `primary_literature` share).
- CI matrix green rate.
- Named defects, закрытые в ROADMAP с honest remainders.
- Cross-engine equivalence coverage (bowtie / BLAST / FM-index — каждая
  specificity row attributes to engine).
- Outcome data accumulation через `marker_record_outcome()`.
