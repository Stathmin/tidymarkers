# Лекция: подбор KASP-маркеров на R — сквозной разбор по методике

`kasp-slides.qmd` — дек Quarto (reveal.js). Это **live-прогон**: при рендере он
реально запускает пайплайн пакета `kaspexample` на локусе FRI (*Arabidopsis
thaliana*, `AT4G00650`) и на каждом этапе показывает код, таблицу и число.

## Как показать

```bash
sh lecture/render.sh          # = quarto render lecture/kasp-slides.qmd + OligoArrayAux на PATH
# затем открыть _site/lecture/kasp-slides.html в браузере (self-contained, без сети)
```

Прямо в браузере:

- `n` — **заметки докладчика** (в деке есть `.notes` почти на каждом слайде: что
  сказать и на что обратить внимание);
- `s` — режим докладчика (текущий + следующий слайд + заметки + таймер);
- `f` — полный экран; `o` — обзор всех слайдов.

Дополнительно: `quarto preview lecture/kasp-slides.qmd` (живое обновление при
правке исходника), `quarto render ... --to pdf` (раздатка для слушателей).

Требуется: `quarto` CLI (≥ 1.4), восстановленный `renv` + установленный пакет,
`OligoArrayAux` на PATH (его выставляет `render.sh`), и один раз — сеть/кэш
(геном TAIR10, варианты Ensembl, FM-индекс; всё в `kasp_cache_dir()`, не в проекте).

## Структура (по этапам методички)

- **Этап 0.** Что такое KASP; что решает дизайн.
- **Этап 1.** Мишень: качество варианта, последствие, 3'-окно (`pick_target_snp`).
- **Этап 2.** Окно дизайна и подсказка направления (`strand_gc_hint`).
- **Этап 3.** AS-праймер: перебор (обе цепи × длина × мисматч), Tm/GC-окна; почему
  выбран не «самый громкий» (футпринт важнее дискриминации).
- **Этап 4.** Дискриминация и 3'-стабильность (`DECIPHER`, `terminal_dg`).
- **Этап 5.** Общий праймер (Tm ≥ AS, ампликон ≤ 100 bp).
- **Этап 6.** Структурный QC: шпильки, димеры, инвертированные повторы.
- **Этап 7.** Специфичность: 3'-сид (оф-таргеты), in-silico PCR, **FM-индекс**.
- **Этап 8.** Анимация поиска (`design_search.gif`) — как сходится отбор.
- **Этап 9.** Приёмка (14 критериев) и заказ (IDT/LGC).
- **Этап 10.** **Полный чек-лист методички** — каждая рекомендация → функция пакета
  → наш результат (3 слайда).

## Заметки

- Тяжёлые чанки кэшируются (`cache: true`), повторный рендер быстрый.
- Всё генерируемое (HTML, кэш чанков, рисунки) → в `_site/`; в `lecture/` только
  исходники. `_site/` и кэш — в `.gitignore`; `lecture/` — в `.Rbuildignore`.
- Данные реальные: FRI (`AT4G00650`), 1001 Genomes через Ensembl REST.
